# Sample QNX tool artifacts

> **These files are synthetic samples, not a live QNX capture.**
>
> They were generated by [`generate.py`](generate.py) by round-tripping the
> Chronoscope simulation of `models/brake-by-wire.toml` into the exact text
> shapes that `traceprinter`, `slog2info` and `pidin` emit on QNX SDP 8.0.
> They exist so the importers and the model/target reconciliation loop can be
> tried offline, in CI, with no QNX licence or hardware. A real capture is
> obtained on a QNX 8.0 target with the commands in
> [`target/README.md`](../../target/README.md). No claim of on-target
> execution is made — see the verified-vs-requires-hardware table there.

| File | QNX tool it mirrors | Consumer |
| --- | --- | --- |
| `traceprinter.txt` | `traceprinter -f tracebuffer.kev` | `parse_traceprinter()` |
| `slog2info.txt` | `slog2info -b chronoscope` (full line format) | `parse_slog2info()` |
| `chrono-stderr.txt` | Chronoscope probe's stderr fallback (bare `CHRONO` lines) | `parse_slog2info()` |
| `pidin.txt` | `pidin -F '%P %T %n %p %S'` | `parse_pidin()` |
| `simulated-trace.json` | `chronoscope simulate --out` | `chronoscope reconcile` |

## Try them (from the repository root)

```sh
python3 examples/traces/generate.py          # regenerate deterministically

python3 -m chronoscope import examples/traces/traceprinter.txt \
    --format traceprinter --audit
python3 -m chronoscope import examples/traces/slog2info.txt \
    --format slog2 --audit
python3 -m chronoscope import examples/traces/chrono-stderr.txt \
    --format slog2 --audit
python3 -m chronoscope import examples/traces/pidin.txt --format pidin

python3 -m chronoscope reconcile examples/traces/simulated-trace.json \
    examples/traces/traceprinter.txt
```

The `traceprinter` sample includes `PROCESS:PROCCREATE`, `prio:<n>` tags,
`THREAD:THRUNNING` / `THREPLY` states, `KER_CALL:MsgSend()` and `KER_CALL:MsgReply()`,
`INT_ENTR`/`INT_EXIT` and the separate `CHRONO` annotation class. Because it is
a Chronoscope round-trip export, importing it should reconstruct the same
deadline KPIs as auditing `models/brake-by-wire.toml` directly.

## Replacing them with a real QNX 8.0 capture

On a QNX 8.0 target (QEMU x86_64 or Raspberry Pi 5):

```sh
tracelogger -d1 -f /tmp/chronoscope.kev -n 8 -s 3
traceprinter -f /tmp/chronoscope.kev > /tmp/qnx-kernel-trace.txt
slog2info -b chronoscope > /tmp/chronoscope.slog
pidin -F '%P %T %n %p %S' > /tmp/pidin.txt
```

Pass those paths to the same `import` / `reconcile` commands. The importers do
not care whether the file came from a target or from this generator — that is
the point of the shared `Trace` format.
